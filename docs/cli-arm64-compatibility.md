# Проверка входа в Antigravity CLI на ARM64

Исправление для [issue #12](https://github.com/vezlin1/antigravity-bypass-russia/issues/12).
Дата проверки: 2026-10-01.

## Причина и изменение

Профиль `agy-arm64-v1` изменял проверку в
`authclient.(*PersonalAuthValidator).Validate`, но оставлял отдельную проверку
в `backend.(*ServerBackend).handleAuthResult.func1`. Последняя формирует
`Eligibility check failed` при входе в CLI. Обе проверки присутствуют
в официальных macOS ARM64-бинарниках CLI 1.2.10 и 1.2.14.

Профиль `agy-arm64-v2` требует ровно одну исходную или уже изменённую
сигнатуру каждой проверки в исполняемых секциях. В проверке входа он заменяет
только `LDRB W2,[X0,#8]` на `MOV W2,#1`. Проверки ошибки и нулевого указателя,
адреса переходов и сам объект результата остаются прежними. Профили IDE,
language server не изменены. Отдельное исправление обработки смешанных x64
патчей описано в [безопасном откате после обновления](update-rollback-safety.md).

Перед записью проверяются выравнивание инструкций, совпадение адресов двух
переходов к успешной обработке, отдельный адрес обработки ошибки и границы
секции для всех переходов этой сигнатуры. Отсутствующая, неоднозначная или
изменённая сигнатура приводит к отказу без записи файла и без создания backup.
Это ограничивает поддерживаемые варианты машинного кода; новый выпуск CLI
нельзя считать совместимым только по номеру версии.

## Обновление и откат

Старый ARM64-патч определяется как частичный. При наличии журнала обновление
сохраняет первоначальный backup и проверяет хеш текущего файла. Потерянный
или несогласованный журнал во время обновления не превращает частично
пропатченный файл в новую исходную копию. Повреждённый backup и посторонние
изменения приводят к отказу от записи. Состояние после прерванной замены
восстанавливается по хешу предшествующего файла.

Без журнала принимается только `.bak`/`.original`, из которого прежний
профиль воспроизводит текущий файл побайтно. Если такой копии нет,
нужно переустановить исходный CLI. Подписанный сторонней программой файл
без соответствующего журнала может не пройти это сравнение; угадывать
его исходное состояние нельзя. Откат восстанавливает точные исходные байты.

## Регрессии

Обычные тесты проверяют обе сигнатуры, идемпотентность, старый частичный
патч, отсутствие и дублирование проверок, изменение переходов и выравнивания,
миграцию, прерванную запись, новый upstream-файл и отказ при повреждении
backup/журнала или пользовательской правке.

```text
cargo test --locked --all-targets
python tests/verify_cli_profiles.py
```

Вторая команда загружает закреплённые официальные macOS-бинарники,
проверяет SHA-256 и запускает только специальные fixture-тесты:

| CLI | Архитектура | Что проверяется |
|---|---|---|
| 1.2.10 | ARM64 | Оба участка, миграция v1, повторный патч, точный откат |
| 1.2.14 | ARM64 | Оба участка, миграция v1, повторный патч, точный откат |
| 1.2.14 | x64 | Один участок, миграция v1, повторный патч, четыре изменённых байта и точный откат |

Fixture-тесты используют временные копии и не запускают Antigravity CLI.
На macOS проверки обеих архитектур также проходят штатную переподпись `codesign`.
Команда добавлена в CI для Windows, macOS ARM64 и macOS Intel. Можно передать
`--fixture-dir` для проверяемого локального кеша и `--target` для Cargo.

Локальная проверка выполнялась на Windows. Вход с реальным аккаунтом,
ответы модели и выполнение `codesign` на macOS здесь не проверялись.
Перед выпуском нужны успешный macOS CI и проверка входа на затронутом Mac.
