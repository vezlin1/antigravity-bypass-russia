# Провайдеры DNS и наблюдение за моделью

Конфигурация `network.json` создаётся при настройке подключения:

- Windows: `%LOCALAPPDATA%\AntigravityBypass\network\network.json`.
- macOS: `~/Library/Application Support/AntigravityBypass/network/network.json`.

Служба читает настройки того пользователя, который включил обход. После изменения
провайдеров повторите настройку подключения, чтобы обновить системные правила DNS,
физические маршруты и закреплённые IP. Процесс DNS перечитывает список при запросах;
ответы из кэша предыдущей конфигурации не используются.

Пример настройки дополнительных провайдеров (адреса `.example` и `192.0.2.0/24`
демонстрационные, замените их своими):

```json
{
  "doh": [
    {
      "name": "my-doh",
      "url": "https://resolver.example/dns-query",
      "bootstrap": ["192.0.2.10"]
    }
  ],
  "extra_udp": [
    {"name": "my-udp", "addresses": ["192.0.2.20"]}
  ],
  "disabled_providers": ["comss.one"],
  "provider_order": ["my-doh", "my-udp", "geohide.ru"],
  "watch_region_errors": true
}
```

Порядок по умолчанию: `dns-ai.ru` (DoH), `comss.one` (UDP), `geohide.ru` (UDP).
У dns-ai.ru три bootstrap-адреса: `192.144.59.14`, `186.246.49.127`, `94.232.43.149`.
Поле `doh` заменяет список DoH;
пустой массив отключает этот транспорт. `disabled_providers` отключает указанные
имена, включая встроенные; должен остаться хотя бы один провайдер. Имена уникальны
и чувствительны к регистру. В `provider_order` перечисляются предпочтительные
провайдеры, остальные следуют за ними. Если позиция `dns-ai.ru` явно не указана,
он остаётся первым. Подмена для конкретного домена имеет больший
приоритет, чем положение в списке: обычный ответ Google не вытесняет подмену.
При чтении старой конфигурации прежние два стандартных bootstrap-адреса дополняются
третьим, а ссылки на удалённый встроенный Xbox DNS убираются из порядка и списка
отключений. Пользовательские адреса и URL сохраняются; файл при чтении не перезаписывается.

DoH использует HTTPS с проверкой сертификата и имени сервера, без системного HTTP
proxy. Bootstrap задаёт адрес подключения, сохраняя имя сервера для TLS. Эти IP не
записываются как UDP nameserver. DoH обслуживается локальной DNS-службой на Windows
и macOS. При недоступной службе доступны прямые резервные UDP DNS; если включён
только DoH, настройка завершается ошибкой. IPv4 bootstrap и дополнительные UDP IP
включаются в физические маршруты на Windows. Без bootstrap разрешение имени DoH
сервера зависит от системного DNS.

При выборе закреплённых IP выполняются полный TLS handshake, проверка системным
хранилищем доверия, проверка имени и HTTP HEAD. Ответы 401/403/404 не означают отказ
TLS и не доказывают доступ к модели. HTTP 5xx, TLS alert, неверный сертификат и
таймаут исключают адрес. Старый IP проходит ту же проверку. При полном провале
подбора прежний файл `hosts` и сохранённый рейтинг остаются на месте.

Команда `report` добавляет `checks.dns_capabilities`: результат для каждого активного
провайдера и проверяемого домена Antigravity/Studio. Номер провайдера соответствует
`checks.configuration.active_providers`. Статусы `substituted`, `PASSTHROUGH`,
`sibling`, `unknown`, `no_addresses`, `timeout_or_error` описывают DNS-проверку.
Сравнение с эталонным DNS — эвристика маршрутизации, а не проверка модели или
аккаунта. Пользовательские имена провайдеров и URL не экспортируются.

`status`, экран меню, проверка подключения и `report` читают последние события
журналов при открытии. Наблюдение пассивное: оно не отправляет запросы модели и не
переключает маршруты. По умолчанию проверяются каталоги `logs` продуктов Antigravity,
Antigravity IDE и Google Antigravity в AppData/Roaming или Library/Application Support.
Массив `log_roots` позволяет указать другие абсолютные пути, в том числе журналы CLI.
`watch_region_errors: false` отключает чтение журналов.

Поддерживаются файлы `.log` и их ротации с `language_server`, `language-server` или
`antigravity` в имени, даты ISO и стандартные Go log timestamps. Учитываются события
за 15 минут: `StreamGenerateContent` с `ResponseID`, региональный отказ, требование
верификации и ошибка запроса. Начало ответа **не подтверждает завершение**. Старые,
неизвестные и не имеющие времени строки не превращаются в положительный статус.
Последняя ошибка отдельно сохраняется в сводке текущего временного окна, даже если
после неё зарегистрировано начало нового ответа.

Чтение ограничено числом файлов, размером и временем; неполный результат отмечается
`partial`. В отчёт попадают только категории и время событий, без строк журналов,
ResponseID, текстов запросов, токенов и путей. Поле `model_access` по-прежнему указывает,
что утилита сама не проверяла доступ; наблюдения находятся в `checks.model_observation`.
