# 🚀 Antigravity Bypass Russia 3.0.1

**Исправление входа в новые версии Antigravity CLI на x64 и работы на Linux с FUSE-монтированиями.**

## 🐞 Исправлено

### 💻 Вход в Antigravity CLI (`agy`) на x64
- Исправлен патч для новых версий Antigravity CLI (`1.5.15+`, включая `1.5.17`) на процессорах x86_64 (Windows, Linux и macOS Intel). В предыдущей версии патч затрагивал только служебную проверку и мог не снимать ограничение при входе.
- Если CLI уже был пропатчен версией 3.0.0, утилита сама увидит это, восстановит исходный участок из резервной копии и применит обновлённый патч.

### 🐧 Linux с `rclone`, `sshfs` и другими FUSE-монтированиями
- Утилита больше не останавливается на этапе «Не удалось проверить, закрыто ли приложение» из-за предупреждений `lsof` о посторонних FUSE-монтированиях (например `rclone` или `sshfs`), если файлы самого Antigravity лежат на обычной файловой системе.
- Ошибки прав доступа, предупреждения для обычных дисков и реально открытые файлы Antigravity по-прежнему блокируют запись.

## ⬆️ Как обновиться
1. Скачайте файл для своей системы из списка ниже.
2. Запустите его и нажмите **`1`** (**Включить обход**). Утилита обновит патч Antigravity CLI, сохранив рабочие настройки сети.
3. Что-то пошло не так? Пункт **`6`** вернёт всё как было.

Если не работает, выберите **`7`** и [создайте обращение](https://github.com/vezlin1/antigravity-bypass-russia/issues/new)
с этим файлом, так мы быстрее разберёмся.

### Патч Antigravity CLI (x64)
- Добавлен профиль `agy-x64-backend-v4` для новых сборок Go, в которых `handleAuthResult` держит `*AuthResult` в `RCX` после проверки ошибки в `RAX`. Проверяются переходы, совпадение целевого адреса и вызов `IneligibilityFromResult` в пределах пролога функции (`0..=64` байта), а диагностическая функция остаётся нетронутой.
- Бинарники, ранее пропатченные по диагностической функции старым профилем, определяются как частично пропатченные и перепатчиваются из проверенного backup (как из журнала, так и из `.bak` с учётом `hub`-патча).
- Обновлены закреплённые версии официальных сборок Google: текущие App 2.35.2, IDE 2.8.0 и CLI 1.5.17; предыдущие App 2.34.0, IDE 2.7.0 и CLI 1.5.13. В `verify_cli_profiles.py` явно проверяется ожидаемый профиль для x64 (`agy-x64-cli-hub-v3` и `agy-x64-backend-v4`).

### Linux и FUSE
- В `linux_lsof_stderr_is_safe` разрешены предупреждения `lsof: WARNING: can't stat() fuse.*` для посторонних точек монтирования, если все целевые файлы Antigravity успешно разрешаются через `canonicalize()`, лежат вне этой точки монтирования (включая алиасы WSLg) и сами не находятся на FUSE (`statfs`, `FUSE_SUPER_MAGIC`).
- На странице «Подробности» описано поведение проверки `lsof` с FUSE и обходной путь через `unshare` на случай, если сами целевые файлы находятся на FUSE.

### Инфраструктура и CI
- В `.github/scripts/ci.py` и `checks.yml` убрана гонка при скачивании собранных артефактов между REST API и `actions/download-artifact`: `wait-artifact` скачивает, проверяет SHA-256 и распаковывает артефакт через REST API с повторами (совместимо с Python 3.10 на `ubuntu-22.04`).
- В `release.yml` публикуются только 6 именованных файлов релиза.
