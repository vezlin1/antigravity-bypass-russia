# 🚀 Antigravity Bypass Russia 3.1.0

**Надёжнее выбор серверов, понятные ошибки вместо «не работает», исправления для macOS и поддержка Antigravity 2.36.0 и CLI 1.5.18.**

## 🐞 Исправлено

### 🌐 Подключение
- Утилита больше не выбирает прямые адреса Google вместо прокси. Такие адреса проходили проверку связи, но запросы к модели отклонялись по региону. Прямой адрес Google используется, только если он действительно идёт через VPN.
- Фоновая служба отвечает Antigravity только проверенными адресами серверов. Раньше она могла передать адрес неработающего сервера, полученный от DNS-провайдера.
- Если файл `hosts` защищён антивирусом или атрибутом «только чтение», утилита снимает атрибут, а если запись всё равно запрещена — настраивает обход через системный DNS Windows и предупреждает об этом.
- Повреждённый блок утилиты в `hosts` (например, после прерванной записи) теперь исправляется автоматически. Прежний файл сохраняется рядом как `hosts.antigravity-bypass.bak`, чужие строки не трогаются.

### 🍏 macOS
- Antigravity 2.35 и новее: утилита больше не пытается изменить служебный файл `agy-desktop-rtc` и не завершает настройку ошибкой «Версия не поддерживается».
- Перед изменением файлов внутри приложения утилита проверяет разрешение «Управление приложениями». Если его нет, приложение не трогается, а утилита подсказывает, где его включить и для какой программы (Терминал, iTerm и т. п.).
- Резервные копии и служебные файлы больше не хранятся внутри приложения: они сами по себе нарушали его подпись. Копии от прошлых версий переносятся автоматически при следующем включении или откате.
- Главный экран больше не показывает «устаревшую версию» фоновой службы, когда она актуальна, а пункт 1 не переустанавливает службу без необходимости.

### 🧩 Совместимость
- Поддержка Antigravity 2.36.0 и Antigravity CLI 1.5.18 проверена на официальных сборках Google.

## 💬 Понятные причины ошибок
- Если локальный DNS-порт занят другой программой (AdGuard, VPN, DNS-фильтр), утилита называет её и её номер процесса.
- Если ни один DNS-провайдер обхода не отвечает из вашей сети, утилита прямо говорит об этом и советует подключиться к другой сети или включить VPN.
- Советы по файлу `hosts` учитывают систему: путь Windows на Windows, `/etc/hosts` и `sudo` на macOS и Linux.

## 🩺 Диагностика (пункт `7`)
- В отчёт попадает последняя попытка включения или отката с кодом ошибки, без путей и личных данных.
- Показывается реальное состояние фоновой службы: работает, не отвечает, не запущена, конфликт DNS-порта.
- Отчёт находит в журналах Antigravity CLI ошибку «User location is not supported».
- Для файлов, которые не удалось настроить, указываются профиль, причина и контрольная сумма — так проще добавить поддержку новых версий.

## ⬆️ Как обновиться
1. Скачайте файл для своей системы из списка ниже.
2. Запустите его и нажмите **`1`** (**Включить обход**). На macOS заранее включите для Терминала разрешение: Системные настройки → Конфиденциальность и безопасность → Управление приложениями.
3. Что-то пошло не так? Пункт **`6`** вернёт всё как было.

Если не работает, выберите **`7`** и [создайте обращение](https://github.com/vezlin1/antigravity-bypass-russia/issues/new)
с этим файлом, так мы быстрее разберёмся.

### Выбор маршрутов и релей
- `address_allowed_for_ranking`: прямые IP Google допускаются в рейтинг только при маршруте через VPN (Windows, исключая оверлейные сети); такие записи отбрасываются и при чтении старого rank-файла.
- `looks_google` сверяет точные CIDR-блоки Google Front End (добавлены `108.177.0.0/17`, `209.85.128.0/17`, `172.253.0.0/16`, `142.250.0.0/15`, `192.178.0.0/15` и IPv6-сети Google).
- Релей отвечает на A-запросы хостов Agent текущим закрепом из `hosts`, а без него — лидером rank-файла (перечитываются раз в 5 с). Хост без проверенного адреса обслуживается как раньше.
- Если ни один DoH-провайдер не ответил ни по одному хосту Agent и маршрут не найден, настройка останавливается с явной ошибкой (`doh_unreachable`).
- Повторы обновления резервных адресов идут с нарастающей задержкой, одинаковые ошибки пишутся в журнал один раз.

### `hosts`
- Снятие и восстановление атрибута «только чтение» при записи (Windows).
- При отказе доступа и отсутствии устаревших закрепов Agent в `hosts` обход завершается через NRPT и релей (`hosts_write_blocked`, итог «Обход включён, но есть замечания»).
- Ремонт повреждённых маркеров блока: удаляются маркеры и строки «IP + домены Google» внутри них, остальное сохраняется; без резервной копии запись не выполняется.

### Поиск установок
- `is_agy_cli_name` принимает только CLI и его архитектурные/версионные варианты; `agy-desktop-rtc`, `agy-helper` и подобные исключены.
- `app.asar` приложения Antigravity без кода IDE не считается целью патча; его версия по-прежнему попадает в отчёт.

### macOS
- Проверка записи `open(O_WRONLY | O_NOFOLLOW)` до изменения файла бандла; при `EPERM` — подсказка с именем приложения запуска и код `app_management_blocked`.
- Резервные копии файлов бандла: `~/Library/Application Support/AntigravityBypass/patch-backups/`. Старые `.ag-backups` переносятся с проверкой содержимого.
- Копия для подписи создаётся в `/private/tmp`; журнал атомарной записи ведётся рядом с бандлом на том же томе, завершённые журналы и пустой каталог удаляются после операции.
- `post_write_hook` снимает только `com.apple.quarantine` с записанного файла; ошибка попадает в журнал и отчёт (`xattr_failed`).
- Версия фоновой службы сравнивается по записанным хешам исходного файла и установленной копии (`service-source.sha256`), так как копия переподписывается `codesign`.

### Диагностика
- `last_attempt`: операция, итог, первая ошибка и до 16 ошибок по шагам с кодами из фиксированного списка, номер ошибки ОС, известный хост Google, факт и итог автоматического отката.
- Состояние службы (`running`, `running_binary_mismatch`, `running_not_responding`, `registered_not_running`, `port_53_conflict` и др.), признак чужого DNS-сервера на порту 53 и `port_53_owners`.
- Каталог журналов Antigravity CLI (`~/.gemini/antigravity-cli/log`) добавлен в наблюдение; стандартный список каталогов в `network.json` дополняется автоматически.
- Для неизвестных и частично пропатченных файлов: имя файла, `sha256`, профиль, причина и число совпадений сигнатур; источник установки (`manual`, `standard`, `path`).
- Проверки доступности `gemini.google.com` и `aistudio.google.com`.
