## «Antigravity повреждено» на macOS (#63)

Воспроизведено на Mac разработчика. Хронология `syspolicyd`:

1. Первый запуск Antigravity.app: Gatekeeper проверяет подпись Google
   (`team EQHXZ8M8AV`), пользователь подтверждает открытие.
2. macOS записывает на приложение `com.apple.provenance`.
3. Утилита заменяет `Contents/Resources/bin/language_server` и создаёт рядом
   `language_server.ag-backups/`.
4. При следующем запуске Gatekeeper перепроверяет приложение
   (`evaluateScanResult: 3`), видит `a sealed resource is missing or invalid`
   и завершает процесс (`Terminating process due to Gatekeeper rejection`).

Факты:

- Карантина на приложении нет, `xattr -cr` не помогает.
- `xattr -cr` и `codesign --force --deep --sign -` под `sudo` завершаются
  `Operation not permitted`.
- Подпись `.app` после замены вложенного файла недействительна всегда. Лишними
  в бандле считаются и изменённый `language_server`, и папка бэкапов.

Гипотеза, которую надо подтвердить: у части пользователей всё работает,
потому что обход включали до первого запуска Antigravity. Тогда `provenance`
ещё нет, утилита снимает карантин, и при первом запуске macOS не проверяет
подпись. Совет «откатить, открыть один раз, включить снова» ведёт именно к
этой ошибке.

Эксперимент: удалить Antigravity.app, поставить заново из DMG, не открывать,
включить обход, затем открыть.

Восстановление: пункт 6 (откат), затем
`codesign --verify --deep --strict --verbose=2 /Applications/Antigravity.app`.
Если подпись не прошла, переустановить приложение из DMG.

## Задачи

1. macOS: перед патчем файлов внутри `.app` проверять `com.apple.provenance`;
   если атрибут есть, приложение не трогать и объяснить, что делать.
2. macOS: хранить бэкапы патча вне `.app`, в каталоге данных утилиты.
3. macOS: не игнорировать ошибки `xattr` в `post_write_hook`, записывать их в
   журнал и `last_attempt`.
4. Релей: для хостов Agent отвечать проверенными адресами из rank-файла, а не
   сырым ответом DoH. Для пропущенного `cloudcode-pa` решить: проверенный
   адрес daily (если прокси работает по SNI) или быстрый отказ.
5. Явная ошибка, когда недоступны все DoH-провайдеры (#60).
6. Реальная проверка доступа к модели в диагностике (#49, #50, #52, #62).
7. Путь к hosts в подсказке брать по платформе (`menu.rs`).
8. Проверить Linux в WSL и сборку на Mac перед выпуском 3.0.2; поднять версию,
   написать `docs/releases/v3.0.2.md`.
