## «Antigravity повреждено» на macOS (#63)

Воспроизведено на Mac разработчика. Хронология `syspolicyd`:

1. Первый запуск Antigravity.app: Gatekeeper проверяет подпись Google
   (`team EQHXZ8M8AV`), пользователь подтверждает открытие.
2. macOS записывает на приложение `com.apple.provenance`.
3. Утилита заменяет `Contents/Resources/bin/language_server` и создаёт рядом
   `language_server.ag-backups/`.
4. При следующем запуске Gatekeeper перепроверяет приложение
   (`evaluateScanResult: 3`), видит `a sealed resource is missing or invalid`
   и завершает процесс (`Terminating process due to Gatekeeper rejection`).

Контрольные проверки на macOS 27.2.1 (26B131), 27 ноября 2026 года.
Основная установка уже была 2.36.0. В ней `codesign --verify --deep --strict`
показал `file modified` для `language_server` и два `file added` для
`language_server.ag-backups`. У бандла были `com.apple.macl` и
`com.apple.provenance`. Для экспериментов использовались отдельные копии
2.35.2 из DMG и команды работы с файлами.

| Сценарий | Результат | Подпись, атрибуты и системный журнал |
|---|---|---|
| A. Запуск после патча из Терминала с разрешением | Контрольный 3.0.1 заменил `language_server`, затем IDE запустилась. Ошибка профиля `agy-desktop-rtc` возникла отдельно. Ранее запуск после патча подтверждён и на `a3f3469`. | `codesign` и `spctl` сообщили `a sealed resource is missing or invalid`. У копии были `macl`, `provenance` и `quarantine` с флагами `01c1`. После статической оценки с `GK evaluateScanResult: 3` Launch Services запустила IDE и её дочерние процессы. |
| B. Процесс без разрешения | 3.0.1 получил `EPERM` при создании временной копии для подписи. Новый код получил `EPERM` при открытии на запись ранее пропатченной копии с журналом 3.0.1. Диагностика нового кода дала `app_management_blocked` и `os_error: 1`. | После отказа 3.0.1 подпись чистой копии прошла `codesign --verify --deep --strict`. У неё были `macl`, `provenance` и `quarantine`. В `sandboxd` есть `kTCCServiceSystemPolicyAppBundles denied by TCC`. Проверку без разрешения проводили из другого приложения запуска. |
| C. Первый запуск после патча | 3.0.1 заменил `language_server` из Терминала с разрешением. macOS показала запрос и позднее завершила PID 3404. | До первого запуска на копии уже присутствовали `provenance` и `quarantine` с флагами `0181`. `codesign` выявил изменение ресурса и добавленный журнал. В `syspolicyd` в 21:19:36 было `Prompt shown (1, 0), waiting for response`, в 21:27:23 — `Terminating process due to Gatekeeper rejection: 3404`. |

На защищённой копии открытие файла с `O_WRONLY | O_NOFOLLOW` без усечения
вернуло `EPERM` из процесса без разрешения и прошло из Терминала. После
обеих проверок подпись чистой копии оставалась целой. Эта проба использует
решение ядра для конкретного файла и процесса. Чтение TCC.db не требуется.
Наличие `com.apple.provenance` само по себе не предсказывает запуск.
На копии, которая успела обновиться до 2.36.0, тот же процесс смог открыть
файл на запись. Результат для одной установки нельзя переносить на все бандлы.

Изменения для #63:

1. Утилита проверяет доступ к файлу до записи. При `EPERM` она показывает
   приложение запуска, если его удалось определить, и путь
   Системные настройки → Конфиденциальность и безопасность → Управление приложениями.
2. Бэкапы файлов бандла хранятся в
   `~/Library/Application Support/AntigravityBypass/patch-backups/`.
   Откат переносит старые `.ag-backups` и восстанавливает исходный файл.
   Незавершённые записи обнаруживаются в обоих форматах.
3. Временную копию подписывают вне `.app`. Подстановку и журнал транзакции
   готовят рядом с бандлом после проверки, что каталог на томе файла.
4. `post_write_hook` обрабатывает только карантин временного файла службы.
   Ошибка удаления записывается в журнал и в `last_attempt` как
   `xattr_failed`. Отсутствующий атрибут считается штатным случаем.
5. Пробного запуска нет. Вариант, при котором утилита сама открывала
   Antigravity через Launch Services и откатывала файлы при отказе или
   таймауте, отклонён: приложение неожиданно открывалось бы при каждом
   включении обхода, а таймаут на медленном Mac тихо отменял бы настройку.
   После изменения файлов внутри `.app` утилита только подсказывает: если
   macOS сообщит, что Antigravity «повреждено», выберите пункт 6.

Сквозные сценарии A и C с новой сборкой не завершены. После перезагрузки
проверку продолжили на уровне файлов и изолированных тестов, без запуска IDE.
На тестовой копии 2.36.0 со старой папкой бэкапов откат вернул `Restored`,
перенёс журнал из бандла, а `codesign --verify --deep --strict --verbose=2`
подтвердил `valid on disk` и `satisfies its Designated Requirement`.

Восстановление: пункт 6 (откат), затем
`codesign --verify --deep --strict --verbose=2 /Applications/Antigravity.app`.
Если подпись не прошла, переустановить приложение из DMG.

## Задачи

1. macOS: выполнить сквозной прогон новой сборки в сценариях A–C.
2. Сделано: вынесены бэкапы и подготовка записи для файлов внутри `.app`.
3. Сделано: ошибки `xattr` в `post_write_hook` попадают в журнал и `last_attempt`.
4. Сделано: релей отвечает на A-запросы хостов Agent текущим закрепом из
   `hosts`, а без него — лидером rank-файла (перечитываются раз в 5 с). Для
   хоста без проверенного адреса (пропущенный `cloudcode-pa`) остаётся ответ
   DoH: выбор между адресом daily и быстрым отказом открыт.
5. Сделано: если ни один DoH-провайдер не ответил ни по одному хосту Agent и
   маршрута нет, настройка завершается явной ошибкой с советом сменить сеть;
   в отчёте о попытке — `doh_unreachable` (#60).
6. Сделано частично: запрос без ключа регион не показывает — Google проверяет
   ключ раньше региона (`API_KEY_INVALID`). Вместо этого диагностика читает
   журналы CLI (`~/.gemini/antigravity-cli/log/cli-*.log`) и распознаёт
   `User location is not supported` (#50, #52). Стандартный список каталогов
   журналов в `network.json` дополняется автоматически.
7. Сделано: путь к hosts и советы в `menu.rs` зависят от платформы.
8. Сделано: при занятом порте 53 ошибка и диагностика (`port_53_owners`)
   называют программу и PID (Windows — `GetExtendedUdpTable`, Linux — `ss`).
9. Проверить сборку на Mac перед выпуском 3.0.2; поднять версию, написать
   `docs/releases/v3.0.2.md`.
