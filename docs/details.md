# Подробности

Техническое описание для тех, кому интересно, как устроена утилита. Для обычной
работы достаточно [README](../README.md).

## Как это работает

Утилита работает точечно и полностью локально на вашем компьютере.

- **Выборочная маршрутизация (SmartDNS).** Через локальный DNS-релей идут только
  служебные запросы к серверам Google AI. Остальной трафик через него не проходит.
- **Локальный патч региона.** Утилита снимает внутреннюю проверку страны в ядре
  Antigravity, поэтому можно пользоваться основным рабочим аккаунтом.
- **Скорость.** Задержка зависит от DNS, выбранного узла и времени ответа модели.

Программа не сохраняет пароли, не перехватывает SSL-сертификаты, не читает ваш код
и не собирает телеметрию.

Подробно о DNS-провайдерах, файле `network.json` и наблюдении за моделью:
[network-providers.md](network-providers.md).

## Что поддерживается

- **Antigravity IDE**;
- **приложение Antigravity** (`language_server`) для процессоров x64 и ARM64;
- **расширения Antigravity** для Visual Studio Code, Cursor, Windsurf,
  VS Code Insiders и VSCodium;
- **Antigravity CLI** (`agy`).

## VPN на Windows

Пункт **[1] Включить обход** следует маршрутам Windows при включении и отключении
VPN и запускает Antigravity с запасным CONNECT на случай блокировки локального DNS.

Если VPN блокирует локальный DNS утилиты, веб-версии Gemini и AI Studio при
включённом VPN работают через него, а после отключения VPN фоновая служба сама
включает для них обход, перезапускать утилиту не нужно. При повторном включении
VPN эти сайты снова передаются ему. После смены сети может потребоваться повторить
запрос, который уже выполнялся.

Подробнее: [Автоматическое подключение Windows](network-providers.md#автоматическое-подключение-windows).

## Резервный сервер daily

Если основной сервер `cloudcode-pa.googleapis.com` недоступен из вашей сети,
настройка не прерывается: на Windows и macOS Antigravity App, IDE и CLI
переключаются на резервный адрес daily. После этого перезапустите Antigravity и
откройте новый терминал для CLI.

На macOS адрес daily задаётся через `CLOUD_CODE_URL` и сохраняется после
перезагрузки. Подробнее: [network-providers.md](network-providers.md).

## Ошибка «Не удалось подобрать маршрут»

Утилита проверяет каждый домен Antigravity дважды, второй раз через 3 секунды со
свежим ответом DNS. В сообщении указан этап, на котором проверка не прошла:

- **DNS не вернул адресов**: проверьте интернет или добавьте другой DNS-провайдер
  в `network.json`;
- **нет TCP-подключения**: проверьте файрвол, антивирус и Kill Switch в VPN;
- **обрыв TLS**: похоже на блокировку по имени сайта у провайдера: повторите позже,
  попробуйте другую сеть или VPN с обфускацией трафика;
- **сертификат не прошёл проверку**: отключите проверку HTTPS в антивирусе;
- **сервер отвечает ошибкой HTTP 5xx**: релей перегружен, повторите через несколько
  минут.

См. также [#32](https://github.com/vezlin1/antigravity-bypass-russia/issues/32).

## Диагностика

Команда `report` (или пункт **[7]** в меню) сохраняет локальный JSON с результатами
DNS по каждому домену, проверками TLS/HTTP и последними распознанными ошибками.
Пароли, токены и тексты переписок в него не попадают.

## Что делает откат

Пункт **[6] Отключить обход**:

- восстанавливает оригинальные файлы ядра и интерфейса из резервных копий;
- удаляет записи маршрутизации: NRPT на Windows, `/etc/resolver/` на macOS,
  `/etc/hosts` и systemd-службу на Linux;
- сбрасывает системный кэш DNS и кэш сессий V8;
- возвращает прежние `CLOUD_CODE_URL` и `jetski.cloudCodeUrl`. На macOS удаляет
  LaunchAgent `com.antigravity.bypass.daily-endpoint` и помеченный блок в
  `~/.zshenv` (`~/.bash_profile`); остальные строки профиля сохраняются.

Значения, которые вы изменили сами после настройки, откат не перезаписывает.

## Linux

Готовые сборки требуют glibc 2.35+ и OpenSSL 3 (например, Ubuntu 22.04+ или
Debian 12+). Нужны `iproute2`, `procps`, `psmisc`, `lsof` и `sudo`/PolicyKit.

В системах с systemd-resolved сохраняются исходные DNS и домены интерфейса; без него
поддерживается обычный файл `/etc/resolv.conf`. Если другая служба управляет этим
файлом через символическую ссылку, утилита сохраняет её настройки и сообщает о
необходимости отдельной настройки DNS. Для Gemini и AI Studio используется
локальный DNS-релей; обычные домены передаются исходным DNS-серверам. Откат
восстанавливает сохранённые настройки. Без systemd фоновый процесс работает до
перезапуска системы.

Перед патчем закройте приложение. Ошибки проверки `lsof` останавливают запись.

### Если `lsof` не может проверить FUSE-монтирование

Утилита останавливается с ошибкой «Не удалось проверить, закрыто ли приложение»,
если в системе есть FUSE-монтирование, которое `lsof` не может обойти, например
rclone:

```
lsof: WARNING: can't stat() fuse.rclone file system /mnt/yandex
      Output information may be incomplete.
```

В этом случае `lsof` завершается с кодом 1, а неизвестное предупреждение
считается ошибкой проверки, поэтому запись не начинается. Это срабатывание
защиты от ложного «приложение закрыто», а не признак занятого файла: каталог
открывается, держателей целевых файлов нет.

Спрячьте это монтирование в отдельном пространстве имён на время патча:

```sh
sudo unshare -m --propagation private sh -c '
  umount -l /mnt/yandex
  exec antigravity-bypass-russia unlock
'
```

Либо отмонтируйте rclone на время патча. Расширять список разрешённых
предупреждений на все `fuse.*` не стоит: `permission denied` и реальные
держатели файлов должны по-прежнему блокировать запись.

Подробнее: [linux-compatibility.md](linux-compatibility.md).
