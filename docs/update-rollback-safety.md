# Откат после обновления приложения

Откат снимает обход с установленной версии Antigravity. Возврат к прежнему
выпуску приложения требует его полного установщика: копия одного старого
исполняемого файла не восстанавливает согласованный набор ресурсов.

## Версии и исходные копии

* Повторное применение и миграция профиля патча сохраняют первоначальный
  чистый backup этой версии. Старый и смешанный x64 v1/v2-патч проверяются
  вместе со всеми исходными участками. Частичная копия не становится original.
* Когда обновление заменило файл чистой поддерживаемой версией, откат
  возвращает `AlreadyStock`. Прежний журнал архивируется, backups сохраняются.
* Новый патч чистой обновлённой версии создаёт её собственную исходную копию.
  Откат возвращает эту версию, сохраняя обновление приложения.
* Неизвестная версия, несогласованный журнал и повреждённый backup приводят
  к отказу от замены. Без точной исходной копии нужна переустановка этой версии.

## Запись и конкурирующее обновление

Все journal apply/restore и legacy-восстановления используют guarded replacement.
Большая копия и backup готовятся до перемещения целевого файла. Затем текущий
файл захватывается, его содержимое проверяется, а подготовленная замена
публикуется только если целевое имя свободно. Обновление, появившееся под этим
именем, не перезаписывается даже при конфликте в момент публикации.

На Windows handle запрещает конкурирующую запись/удаление захваченного файла.
Перемещение выполняется через этот handle с `ReplaceIfExists=false`; публикация
использует `persist_noclobber`. См. [FILE_RENAME_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_rename_info).

На macOS проверяются процессы, удерживающие уже захваченный файл, через `lsof`.
Ошибка проверки и другой открывший файл процесс отменяют запись. Содержимое
сохранённого файла повторно проверяется после публикации. Unix `flock` является
advisory lock и сам по себе не исключает чужие записи через старый descriptor;
см. [flock](https://man7.org/linux/man-pages/man2/flock.2.html).

Во время замены целевое имя кратковременно отсутствует; операция требует
закрытого приложения. Захваченный файл и маркер сохраняются в скрытом соседнем
каталоге `.имя.ag-transaction-*`. После прерывания восстановление использует
сохранённый inode только при отсутствующем целевом имени и проверенном маркере.
Появившийся файл сохраняется. Завершённые и отменённые транзакции не воскрешают
старые файлы после их последующего удаления пользователем.

Чистые завершённые транзакции очищаются на Windows. На macOS очистка также
требует неизменённого содержимого, отсутствия открытых handles и дополнительных
hard links. Неоднозначные и конфликтующие копии сохраняются для восстановления;
они могут занимать размер полного исполняемого файла. На других Unix такие
копии сохраняются консервативно. Это не гарантия координации с произвольной
программой, передающей открытые descriptors или меняющей дополнительные hard
links. Перед повторным откатом следует завершить обновление приложения.

CLI-операции записи сериализованы существующим single-instance lock: глобальным
mutex на Windows и удерживаемым `flock` на Unix. Статус и диагностика остаются
операциями чтения. Восстановление незавершённых транзакций выполняется отдельно
перед поиском целей для применения и отката, включая временно отсутствующий CLI.

## Настройки IDE и доступ пользователя

Если `settings.json` не менялся после настройки, сохраняется точный откат всех
байтов. При пользовательских правках возвращается только `jetski.cloudCodeUrl`;
новые предпочтения, комментарии, BOM и остальные ключи сохраняются. Если сам
endpoint изменён пользователем, он сохраняется, включая повторный откат.
Прежний локальный endpoint блокирует отключение необходимого ему шлюза.

Новые JSONC-журналы сохраняют проверенные снимки применённых настроек. Для старых
журналов владение ключом подтверждается воспроизведением прежнего изменения и
сравнением SHA-256. Неоднозначный JSONC и повреждённые копии блокируют запись.

Новые каталоги настроек macOS получают владельца профиля и права `0700`, новые
файлы — владельца родителя и `0600` до публикации. Новые каталоги backup и
транзакций также наследуют владельца родителя. Существующие права сохраняются.
Если отсутствующий settings.json должен создаваться в существующем каталоге
другого владельца, операция отказывается от создания недоступного файла.

## Проверки

Регрессии покрывают обновление до отката, обновление во время подготовки и
публикации, удаление нового пользовательского файла, прерванную запись,
повторный запуск, смешанный x64-патч, исходные копии нескольких версий,
пользовательские правки JSONC и обнаружение официального Go CLI.

```text
cargo test --locked --all-targets
python tests/verify_cli_profiles.py
```

Закреплённые официальные CLI 1.2.10 ARM64, 1.2.14 ARM64 и 1.2.14 x64 проверяются
по SHA-256. Во временных копиях проверяются обнаружение, патч, миграция,
повторное применение и точный откат. На macOS проверяется также штатный codesign.
Эта проверка обязательна в release build до упаковки; release job зависит от
успешных Windows/macOS ARM64/macOS Intel сборок.

Локально доступен Windows. Сборка для двух архитектур macOS проверяется без
исполнения; native macOS проверки прав, открытых файлов и codesign требуют CI.
Вход с настоящим аккаунтом и ответы модели этим набором не проверяются.
